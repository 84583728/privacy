Privacy Policy

Video Playback Link Extractor · Last updated November 4, 2026

Version 1.0.6. This independent extension uses adapted Cat Catch media detection and stream download code. Its developer is a partner of ShipLang, not a representative of ShipLang.

Media capture

After you start capture and grant optional site access, the extension observes media response URLs, response MIME types, filenames and sizes in tabs where capture is enabled. A page script also reads media element sources and resource timing entries. On a YouTube tab where capture is enabled, a page-context observer reads the current video’s already-generated playback metadata and observes its legitimate playback request URL and body; a restricted webRequest observer may also read the original Googlevideo SABR request body. These are used locally to prepare the requested download. After you start capture, the extension may request an observed HLS playlist to identify its exact child playlists, initialization files and media segments; these child resources are hidden from the main result list. This classification does not prefetch media files or encryption keys. Parent-child URL relationships remain in the local capture session. It stores detected links, page titles, resource metadata and capture status in browser session storage. Capture continues when its popup closes. Navigating to another site stops capture; closing a tab removes its results, and ending the browser session clears session data. Each tab stores up to five hundred resources.

Detected links and page titles are processed locally and are not sent to ShipLang or the developer. The extension does not collect request cookies or authorization headers, build a browsing history, or upload video contents. Links may themselves contain signed query parameters. You choose which links to copy to the system clipboard.

Downloads and local stream processing

When you click Download for an ordinary video, Chrome requests the original media URL from its media host and saves the resource in your browser download location. For supported HLS or DASH streams, the extension requests the playlist and its media segments, selects a supported quality and default audio track, and combines them into one MP4 on your device. Independent supported fMP4 audio and video tracks are joined locally. A playlist that points to one complete MP4 is downloaded directly by Chrome. Session download jobs store the source URL, page title, progress, status, error code and download identifier to show progress, completion or interruption. Active jobs and up to thirty finished task records remain until the browser session ends, including when their original tab has closed. Processing continues when the popup closes. Keep the original YouTube video tab open during a YouTube download so that its playback context can be refreshed if necessary.

Stream processing uses a hidden extension document and temporary files in the extension’s private local Origin Private File System (OPFS). For standard HLS AES-128, it requests the key URL specified by the playlist and decrypts segments locally with WebCrypto; keys stay in task memory. Media segments, merged data, keys, links and page titles are not uploaded to ShipLang or the developer. Requests go to the media and key hosts and may use existing cookies for those hosts; the extension does not read or store those cookies or authorization headers.

Temporary task files and keys are cleared after completion, failure or cancellation. Files left by an unexpected browser exit are cleaned when the processing document next starts. Saved videos and Chrome’s download history remain until you remove them through normal browser or file controls. Stream processing supports a limited set of common H.264/AAC TS and fMP4 formats, up to 10,000 download items and 24 hours, with a 64 MiB per-segment limit and 4 GiB cumulative network transfer limit per task, including retries; available browser storage may impose a lower limit. Unfinished live streams, DRM/SAMPLE-AES, track or initialization changes, multiple DASH Periods and unsupported formats produce an error.

YouTube playback context and local processing

Version 1.0.6 adds a local SABR/UMP download path for ordinary, non-DRM H.264/AAC YouTube video-on-demand content that the user is already permitted to play. It uses playback context already generated by the current YouTube page, actively requests the video and audio from HTTPS Googlevideo media endpoints, and joins supported tracks on the device after checking their sequence, end-of-stream state and duration coverage. It does not use a third-party parsing, download or conversion server, and it does not install or run a local helper application or FFmpeg. Advertising requests are excluded; the interface waits for the actual video rather than treating an advertisement as the requested file.

Full player-response metadata, signed playback request URLs, original request bodies and playback tokens remain only in the page, background temporary cache and active processing-document memory. They are not written to browser session storage, local account storage or long-term storage, and are not sent to ShipLang or the developer. A current request can remain in temporary memory while capture is enabled for download or retry. Corresponding caches are cleared when capture stops, access is revoked, the video changes or the tab closes; active task context is released when the task ends. Only the display fields needed for the result list, such as video ID, title, duration and page URL, and the download status use the existing browser-session records.

The extension does not itself fetch and execute remote player or BotGuard programs. Expired playback context may be refreshed through the original video page. It does not read account cookies or authorization headers. YouTube and Googlevideo requests may use the browser’s existing session in the same way as ordinary media requests.

Website compatibility and URL handling

Generic detection and local merging do not establish support for every website or every video. The YouTube path targets a limited set of ordinary non-DRM H.264/AAC videos and remains subject to each sample’s full-download and playback verification. It does not promise all videos, regions, account conditions, codecs, live streams or future protocol versions. Arbitrary Googlevideo fragments are not saved as complete videos. Instagram’s independent audio/video pairing is not implemented; explicitly identified independent Meta video tracks are refused with an unsupported-track message, and identified audio-only tracks are hidden from the main video results.

For recognized cdninstagram.com and fbcdn.net hosts, the extension normalizes valid, unambiguous bytestart and byteend range parameters using an adapted Cat Catch rule, while preserving the other query parameters and their encoding. It retains the original request URL and range in local session metadata and reads an explicit DASH encoding label from the URL’s efg field to classify known independent tracks. This Meta URL handling does not infer matching audio and video pairs or provide a complete Instagram downloader. These URLs and labels are not uploaded.

Limited use of data

We use data only to provide the extension’s disclosed media-link capture, copying, downloading and optional account features. We do not sell user data, use it for personalized advertising, or transfer it for unrelated purposes. Our use of information received through Chrome APIs complies with the Chrome Web Store User Data Policy, including its Limited Use requirements.

Permissions

The extension uses webRequest to inspect authorized media responses and the restricted YouTube/Googlevideo playback request body; activeTab to identify the current page; scripting to inspect media sources and existing YouTube playback context in authorized pages; storage for session results, settings, trial accounting and account information; clipboardWrite to complete copies you request; downloads to start your requested downloads and observe their completion or interruption; and offscreen to run local parsing, decryption and merging after the popup closes. Optional HTTP and HTTPS host access covers the page and independent media and key delivery hosts. Browser-level permission may remain granted until you revoke it. Product logic saves resources only for tabs where you started capture. You can revoke access in the extension’s help section or browser settings.

Accounts, membership and service providers

Sign-in and payment occur only when you choose those actions. ShipLang receives the product identifier, extension identifier, UI language, extension version, and, when available, the user identifier and local membership expiration. It stores the email address, avatar and membership expiration needed for login and membership. The extension stores the returned current-product user identifier, email and membership expiration locally. Trial counts, temporary copy reservations and recent completion identifiers remain local.

ShipLang provides AI software development, login and payment infrastructure. Depending on the service selected, account or payment processing may involve Google, PayPro Global or Stripe. Their policies apply to their respective services. Media results are not included in account or payment requests.

Simplified Chinese browser UI users can copy for free. Other UI languages receive ten successful copy operations before membership is required. Capture, viewing and downloading do not consume those copy operations. Membership and trial accounting remain separate from local media processing.

After a user identifier is available, an uninstall feedback URL is registered once. If opened on uninstall, it sends the user identifier, browser UI language and extension version to ShipLang.

As with ordinary website visits, original media hosts and optional account or payment pages receive normal connection information such as the IP address, browser information and requested address. Their privacy policies govern their handling of that information. This extension does not collect precise location or use location inference for product features.

Retention and deletion

Closing a captured tab removes its results. Local settings, trial accounting and account data remain until extension data is removed or the extension is uninstalled. Uninstalling does not cancel a subscription. ShipLang retains account information until you request deletion, with no retained backup. Request deletion at support@shiplang.com, including the extension name or store link and your request and reason. Requests are processed within seven days.
